# Native prototypes

Read [native execution](../ysun-figma/references/native-execution.md) and connect the exact file via [files](../ysun-figma-files/SKILL.md). Use the shared pinned API types for `Reaction`, `Action`, `Trigger` and `PrototypeMixin`. Inspect existing reactions and destination IDs before changing a flow.

The manifest uses dynamic-page access: update reactions with `await node.setReactionsAsync(...)`. Preserve existing interactions unless replacement is requested. Check every destination, trigger, action and transition in the native types before the first write; official remote convenience fields are not native setters.

The pinned official `Trigger` declaration requires `deprecatedVersion` on MOUSE_ENTER/MOUSE_LEAVE, but the live native setter rejects that field, including both true and false. Author these triggers as `{type: "MOUSE_ENTER", delay: 0}` or MOUSE_LEAVE with the required delay. Native read-back and reapplying this shape were verified. Leave the upstream declaration intact; do not infer setter support from a type alone or strip fields inside the executor. `delay` is in milliseconds. ON_HOVER/ON_PRESS revert when the trigger ends; enter/leave/up/down are one-way actions, not a free pointer-following drag/drop API.

CHANGE_TO requires variants in the same actual COMPONENT_SET. Check their parent IDs with lightweight inspect; cloning a component defaults to the current page, so append it to the set first. Native instance children cannot override every transform. Main-component variants or supported instance properties can preserve reuse; a wrapper or detached copy may suit a different task but changes ownership. Choose the model according to the user's intent and the actual API restriction. Verify internal componentPropertyReferences when cloned variants expose text or boolean properties.

`FrameNode.overlayPositionType`, `overlayBackground` and `overlayBackgroundInteraction` are **read-only**. Their presence in a read does not make assignment legal. `overlayRelativePosition` is permitted only for a target configured as MANUAL; a newly created frame is commonly CENTER. Do not assign these fields or add an arbitrary relative position. If exact MANUAL placement is required, set it in the normal Prototype UI when available, then read the persisted state before assigning reactions.

For an overlay that must behave within fixed screen bounds, an editable full-screen transparent overlay frame containing the panel can use the native center overlay behavior. Use the actual destination screen size and panel coordinates, not an invented global offset. Add native close actions where the requested flow needs them. This approach still needs presentation-mode validation; it does not simulate real text input, sign-in or a production application.

Dependencies must exist when reactions reference them; the Agent chooses appropriate operation boundaries. Log IDs after creation if subsequent setters can throw. Errors after execution preserve logs/exports but do not roll back native mutations. Read the original `figma_job` and affected nodes; record `partially_applied` when only part persisted, then finish or remove exact task-owned nodes with a new intentional operation. Do not replay the original request under a new ID.

Native clone copies prototype state, including flow starting points. Read `page.flowStartingPoints` after cloning a screen; retain the intended entry and remove only task-created duplicates. A scroll container can consume ON_DRAG before a nested interaction; inspect the actual layer hierarchy and test the gesture in Present. A stored drag/up reaction or a click substitute does not prove continuous dragging, pointer following or release over a target.

Validate stored reactions, positions and destinations, then open the actual Figma presentation to exercise all requested paths, including close/back/state changes. Check focus, clipping and touch targets where relevant. Use the presentation's actual scaling controls; scale-down can fit a full screen when min-zoom crops it. If presentation disagrees with a newly exported native frame, compare the exact file key and job's client/document/instance first. Native mutation success does not confirm cloud sync. Inspect Figma's actual sync warning; do not force-refresh or close a file with unsynced edits. If the design has no unsynced warning, reopen only that exact presentation and verify the new content; this does not establish which cache or sync layer was responsible. No public Plugin API reports cloud sync completion. A screenshot, a reaction array or an API setter return is not interactive acceptance. Clearly distinguish a visual prototype from real input/data persistence.

# ysun figma 0.35.1 工程审查

2026-11-18 在 Apple Silicon、macOS 27.2.1、Figma Desktop 126.11.8、Node.js 24.19.0 上验收。本机 Codex 已加载 0.35.1。审查涵盖工具契约、传输、文档身份、操作调度、原生执行与查询、文件交付、可选云端接口、安装及更新。公开发布需要单独进行。

## 设计决策

| 问题                                                     | 采用的设计                                                                                                                                                      | 验证证据                                                                                                                         |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 普通文件操作需要多次发现和手动提取文件键                 | 原始链接直接打开或复用精确实例，返回可持续使用的 clientId。单文件请求只取目标目录项。活跃操作与历史计数分开查询                                                 | 官方 SDK 并发发起 25 次已连接文件的打开请求，均命中同一实例，本机这轮中位数 26 ms，P95 为 27 ms                                  |
| 云端写入可以在内存里等待，而调用方尚无可查询回执         | 原生、REST、Widget 先提交到同一 SQLite 账本。已提交的状态变化唤醒本机执行器，按相交文件互斥。维护准入覆盖从 HTTP 受理到任务提交的间隙                           | 200 个唯一操作各提交 5 次，单文件实际执行 200 次且保持顺序。满额的新操作返回 429。独立文件可并行，重叠文件等待                   |
| 超时和答复丢失可能被当成一次新操作                       | 原操作 ID 贯穿提交、执行和交付。已领取的写入失去结果时保留不确定状态。旧实例退出、撤销授权和条件写入冲突均在各自的责任边界处理                                  | 只读和写入两类、6 个执行阶段、3 种中断方式共 36 种组合。实际画布上重复提交只创建一个节点，过期快照阻止脚本执行                   |
| 打开大页面可能超过单次原生结果限额                       | 页面概况逐页返回数量和下一偏移。搜索按父层级及子序号保存位置，恢复前核对文档、修订和父层结构。旧 ID 列表游标可以继续读取                                        | 同一十万直属图层样本，概况从 7,478,151 字节降至 7,319 字节。搜索每次 500 项，200 页按序覆盖全部图层，最大的续页游标为 290 字节   |
| 多文件导出发生故障时，结果交付可能重复执行已经完成的步骤 | iframe 保留不可变的原生结果和每个已确认文件的回执。MCP 校验字节长度及哈希，以排他方式发布完整本地文件                                                           | 分别在第二个文件上传及最终回执阶段注入失败，原生脚本总共执行一次。实机导出的 120 × 48 PNG 与原生回执哈希一致                     |
| 桌面重连、首装和升级可能相互打断                         | 桌面协调器负责实例替换，macOS 按 bundle ID 识别应用。安装器在切换前记录原包与稳定入口，探测通过才提交，恢复失败时保留日志。原生构建标识包含沙箱、UI 与 manifest | 本机从 0.34.20 升级，经候选包切换到 0.35.1，Codex 插件保持启用。自动测试覆盖首次失败、重复恢复、健康探测失败、并发安装及维护准入 |
| 内部错误直接出现在 Figma 窗口                            | 窗口提示用户当前能做的操作，备用连接码默认折叠。底层原因、操作 ID 和恢复信息放在结构化工具结果中                                                                | 检查打包后的 360 × 280 窗口，浅色、深色和展开输入均可读，展开后没有纵向溢出。撤销授权与晚到的任务响应并发时，原生写入不会启动    |

## 复验

- `npm ci` 安装锁定的开发依赖。
- `npm test` 重建交付包并运行 328 项测试。本机 327 项通过，1 项专测全新 macOS 缺少 Figma，因本机已安装而跳过。
- `npm run check` 检查格式、静态规则、构建一致性和发行契约。`npm run api:check` 联网核对固定的官方声明、文档及独立接口目录。
- 回归入口包括 `test/mcp-sdk.test.cjs`、`test/execution-store.test.cjs`、`test/external-jobs.test.cjs`、`test/native-features.test.cjs` 和 `test/ui.test.cjs`。更改原生执行、挂载或桌面连接时，还需通过已授权编辑器完成实际的写入、读回和清理。

本轮实机覆盖一个已登录的桌面环境。Intel、其他 macOS 版本、首次登录、企业席位与权限写入、Dev Mode 内的付费回调、跨设备协同和云端最终保存仍有独立的验收条件。桌面启动和账号目录依赖 Figma Desktop 的部分内部接口，未来的 Desktop 版本需要重新验证。现场单次延迟和合成图层测量的适用范围分别是上述设备和样本。

## 0.35.2 推送验收

首次 GitHub Actions 验证在 Intel macOS 26 与 Node.js 24 上分别观察到两个故障。冷启动进程查询触及原先 5 秒的 AppKit 脚本期限。另一份日志中，两个进程交接安装权时，读取旧 PID 符号链接返回了 `EINVAL`。

0.35.2 使用 LaunchServices 直接判断 Figma 是否在运行，有匹配时再读取 AppKit 进程身份。安装器与桌面管道读取器各自使用内核管理的互斥锁。进程崩溃后，继任者可以获得同一把锁并清理旧标记。旧包和 launchd 的恢复入口仍可识别 PID 标记。新增回归覆盖锁持有者崩溃、旧标记在读取中消失，以及同名普通文件的保留。

在安装了 Figma 的本机，330 项测试中 329 项通过，1 项专测未安装 Figma 的环境并按条件跳过。Codex 已启用 0.35.2，安装目录和 Codex 缓存中的 101 个分发文件均与构建逐字节一致。通过 Codex 从关闭的 Figma Desktop 打开既有 Design 测试文件，原生连接成功，分页概况正确返回当前页和 5 个顶层对象的总数。验收全程只读，结束后已恢复桌面应用原先的关闭状态。

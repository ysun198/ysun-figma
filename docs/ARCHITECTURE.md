# 架构

一个本地伴随服务连接 Codex 与 Figma 原生 Plugin API。工具和工作台共用同一个执行环境，设计文档由 Figma 持有。

## 代码放在哪里

| 目录               | 内容                                                    |
| ------------------ | ------------------------------------------------------- |
| `src/host/`        | Node.js 本机服务：MCP、传输、调度、账号目录、安装和更新 |
| `src/figma/`       | Figma 内运行的原生执行代码、设计查询和连接界面          |
| `src/workbench/`   | Codex 工作台：文件浏览、导航和页面预览                  |
| `src/shared/`      | 跨运行环境使用的协议常量、版本比较和界面样式            |
| `scripts/`         | 构建、检查、打包发布，以及 MCP 的 shell 启动入口        |
| `skills/`          | agent 的任务导航与固定版本的公开 Plugin API 参考        |
| `test/`            | 自动测试，公共辅助代码放在 `test/helpers/`              |
| `docs/`、`assets/` | 公开文档和插件图标                                      |

根目录的 `plugin.json`、`mcp.json`、`manifest.json` 分别描述 Codex 插件、MCP 服务和 Figma 插件。生成内容位于 `build/`，发行包位于 `dist/`，两者都不提交到 Git。

## 执行与恢复

`src/host/mcp.cjs` 将工具请求交给经认证的本机回环服务 `src/host/bridge-server.cjs`，由 `src/host/execution.cjs` 调度原生客户端执行。每次操作需要确切的客户端和文件目标。云文件绑定来自已验证的文件 URL；账号目录发现不授予原生访问权限，标题不能证明文件身份。

每次编辑携带稳定的操作 ID 和请求哈希，待执行输入保存在内存中。SQLite 统一管理操作状态和回执，使用 WAL 与 FULL 同步提交；回执交付与终态一起提交。重复请求返回已有结果。连接中断或重启后，结果不确定的操作保留原始状态，由 agent 检查实际设计并确认结果，随后才能继续编辑。

普通成功调用仅返回操作 ID、状态、目标、结果及非空日志/导出；日志截断仍明确保留。`figma_job` 和失败结果保留完整回执，数据库原始记录不变。状态区分当前范围的 `scopedUnresolvedJobCount` 与全局历史的 `globalUnresolvedJobCount`；返回的 `jobs` 是该范围内的完整未决列表，筛选历史不等于截断。

并发优先使用一次原生读取、计算、修改，避免将可在执行时计算的值带出原生环境。跨调用作出的决定采用乐观条件写入：`figma_snapshot` 将所选原生属性和节点祖先路径保存在已有只读回执中，`figma_run` / `figma_upload_assets` 的 `ifUnchanged` 引用这些回执。提交时核对确切文件和原生实例，值只复制进待执行内存载荷；原生端在全部异步资源查询完成后、脚本开始前核对。冲突属于已知失败，不执行用户脚本、不提交 Undo、不产生不确定写入阻塞。独立区域和不相交的属性不互相失效；共享变量与样式可显式纳入观察。没有额外锁服务、任务数据库、租约或周期保活。

同一文件的任务复用同一个原生客户端，`rootId` 或唯一快照根提供 `bridge.root` 并限定辅助创建的默认父级，不改当前页。Figma 的变量和集合 ID 查询可能保留旧代理；条件依赖这些本地资源时，从对应本地列表读取存在性及最新值，普通图层编辑和空闲状态不枚举变量。原生 JavaScript 仍有完整 API 权限；根不是沙箱，条件检查不提供跨异步脚本、人手操作、其他插件或多设备云同步的事务隔离。仅观察实际依赖的属性，必要时重新读取并合并；运行后的不确定结果仍使用原回执核对和 reconcile。

读取与编辑共用调度器。轻量查找默认不解析实例母组件，详细组件信息仍可显式读取；Motion 默认省略静态图层的空时间线，保留显式根的上下文及完整读取选项。健康检查所得的状态用于该次目标解析，提交时再次核对实例，避免重复状态请求。Figma 原生事件和已完成写入会触发预览刷新；刷新期间保留上一张图像和视口，等待新的整页 PNG，避免与编辑争用读取。工作台的平移和缩放作用于图像视口，图层编辑与原型播放在 Figma 中完成。

`src/host/api-reference.cjs` 提供离线 `figma_api`。[功能索引](../skills/ysun-figma/references/api-map.md)的主题、工作流和功能表同时提供技能入口、中英文任务关键词、工具候选和原生符号，不另存路由表或搜索数据库。工作流返回按需指南正文；任务关键词可解析为准确的声明，未命中的描述返回原生概念供继续发现。精确 MCP 工具名直接返回同一工具定义的当前契约和包版本，用于参数纠正及宿主目录过期时的发现。类型文本及所属类型索引按已加载的不可变包懒加载，版本切换时重建，避免逐次读取和解析。精确检索保留官方来源、行号与截断信息。索引命中、类型声明和实际权限分别验证。技能讲解操作机制，不规定设计风格；[官方技能对照](../skills/ysun-figma/references/capabilities.md)记录云端服务边界。

页面导航、结构读取和全部原生导出统一通过 `bridge.query` 调用 `src/figma/design-queries.js`，不再维护导航/JSON 的独立脚本。`figma_navigate` 使用确切页面、图层和稳定操作 ID，只改变选择及视口，不创建 Undo；它不会把应用带到前台。JSON 导出复用同一节点定位、执行回执、字节校验和文件交付，保留既有返回字段；不声称可替代 .fig 或云端保存。日常查看、编辑、页面导航和导出无需 GUI 自动化。

PNG 在上传时附带实际像素尺寸和透明度诊断；全透明图给出提示，仍交付原字节。不支持的透明度编码或超过 64 MiB 的解码预算返回未知及原因。检查复用 Node.js 内置解压，无运行时依赖、后台轮询或重复截图；正常渲染与设计质量仍由原生预览验收。

同一个 AbortSignal 贯通等待、素材上传、导出下载与写入前检查。停止客户端等待不撤销已经开始的原生编辑，其真实结果仍按原操作 ID 保存。stdio 的 end/close/error 均释放等待资源；畸形的协议参数与工具执行错误分别返回。

页面观察只订阅已加载页面，不重复调用 loadAsync；辅助监控不增加执行回执的云端等待。

到期判断共用一个定时器，在操作、会话、回执或输入资源的下一次实际到期时唤醒；请求入口仍校验过期状态，不维持每秒扫描。过期排队任务在领取前终结，运行任务失联或超时后保留原有不确定结果屏障。服务闲置时，七天回执和 24 小时输入资源仍按期清理。重复上传同一输入资源会刷新使用时间，避免新上传回执立即过期。

设计的日常恢复沿用原生 Undo。重要改动前通过现有 `figma_run` 调用 `saveVersionHistoryAsync`，保留真实版本 ID，无需 .fig 导出或新增备份服务。该接口不保证包含紧接之前的插件编辑，版本创建成功不能冒充最新内容已经完整同步。版本恢复与独立离线 .fig 副本属于另有需要时使用的原生入口，不自动为普通编辑生成副本。

## 适配边界

`src/host/desktop.cjs` 在 Figma 启动时建立当前用户私有的 CDP 管道，确认连接就绪后再通过系统打开文件。Figma 自己持有双向 FIFO，连接进程退出不会关闭编辑器；独占读取避免跨会话争用，消息按请求标识分发。没有 TCP 调试端口，没有另外的浏览器或凭证副本。已由其他方式启动的 Figma 需要正常退出后重连，不能把一个无法接入的进程当作已经接入。

账号目录与 Community 复用 `createPageReader` 管理原生对象引用、调用、释放；各自保留目标选择、认证和分页策略。同一云文件可以绑定多个经实际 URL 验证的原生实例，调用方必须明确歧义，绑定新实例不会隐藏旧实例。

`src/host/catalog-sync.cjs` 与 `src/host/account-reader.js` 在现有 Figma Home 的认证环境中读取账号目录，并订阅 Figma 自己的 LiveGraph 目录和分页数组。多个 Home 页面按真实账号 ID 核对身份，使用已认证的连接；不同账号不自动选择。使用实际账号空间、团队、文件夹标识；不点击导航、不切换筛选、不缓存版本相关的查询哈希。订阅在结束、账号变化或空闲超时后释放。读取最近浏览、草稿、团队及嵌套文件夹、共享入口；只有所有来源到达分页末尾才标记完成，部分失败保留已知文件。

这些是 Figma 当前桌面端的内部接口，不是公开的账号全量 REST API，可能随版本变化。桌面端登录复用和完整目录同步已用免费团队的真实账号验证；组织账号的权限组合尚未完成实机验收。目录发现不授予原生文档访问权限；能力不可用时，已连接文件仍可读写。

`src/host/community.cjs` 和 `community-reader.js` 通过同一私有管道复用已登录的 Home 会话，直接搜索公开 Community 的 Design 模板和 UI kit，读取精确资源详情与封面/轮播预览。此路径只有 GET 读取，不点击导航、不复制登录凭证，也不提交原生编辑任务。账号有歧义时拒绝选择；返回结果采用公开字段白名单，去掉服务令牌、独立联系字段等无关数据。搜索保留真实分页；详情核对数字 Community 文件 ID 和公开范围。预览优先读取发布文件自身的封面，与社区宣传封面、轮播图分别标明来源；仅使用服务返回的 Figma 图片 CDN 地址，不拼接或改写地址，限制格式与大小。部分社区宣传图片的 CDN 会返回 WAF challenge，不能把 202 空响应当图片或把其他图冒充指定轮播。这些社区接口属于可能变化的 Figma 内部服务，失败时不影响原生文件能力；也不代替原生图层检查、授权判断或模板复制。

界面使用宿主主题变量和共享 CSS；内联图标采用有许可证的 Lucide 路径。会话输入由 Codex 持有，插件通过 MCP Apps 提供确切的文件、客户端和页面上下文。

## 构建与检查

修改代码后运行 `npm test` 和 `npm run check`。前者构建并运行自动测试，后者检查格式、静态规则、构建一致性、插件配置与公开内容。原生执行或宿主集成变更还需要在实际编辑器和打包运行时中验收。

`npm run check` 离线校验索引中的原生符号、MCP 工具、指南和参考摘要。`npm run api:check` 通过官方公开 Git 引用取得不可变提交，核对类型文件及官方最新更新记录的语义内容；新增类型、文档变化、网络失败和页面结构变化均不会报告为“已是最新”。CI 执行同一检查。`npm run api:update` 只同步官方类型、许可证和来源信息；维护者仍需检查差异，更新相关指南，不能把下载成功当作功能验收。插件运行时不执行联网更新检查。

构建组合原生代码、打包官方 MCP Apps SDK，并收集依赖许可证。`package.json` 的 `distributionFiles` 是公开运行文件白名单的唯一来源。生成文件由源码构建，不手动维护。私有浏览器状态、宿主应用代码和开发记录不进入源码仓库或发行包。

Node.js 是共享的外部运行依赖，最低主版本由 `package.json` 的 `engines.node` 定义。安装时由 Codex 检查和准备；`scripts/run-node.sh` 统一选择可用运行时，MCP 和每用户更新服务使用同一入口。发行包不包含运行时，插件更新不复制或回滚 Node.js；更新服务内嵌这段启动入口，以便包切换中断后仍能恢复。

一个包版本对应不可变的发行内容。`src/host/installation.cjs` 验证安装回执，原子切换包并保留私有状态；本地只保留当前运行包和切换期间必要的恢复数据。原生构建标识来自源码内容，界面或技能变更无需重启未变化的原生内核。

## 自动更新

`src/host/update-service.cjs` 管理每用户更新服务，`src/host/updates.cjs` 接收 GitHub 发行资源。发布者使用 Ed25519 签署发布描述，客户端验证随包公钥、压缩包哈希和精确文件白名单。

接收器取得维护准入后，阻止新操作跨越切换边界。启动探测通过才提交新包，失败或中断通过恢复日志回滚；启动探测失败的压缩包会被拒绝，等待不同的发行包。排队更新在重试前重新核对发布状态，清理已撤回或被新版替代的候选包。切换或恢复完成后清理暂存目录。

私有 `updates/status.json` 统一保存调度、HTTP 缓存验证信息、签名发布描述和被拒绝的版本。接受 HTTP 304 前重新验证缓存签名。正常检查加入随机错峰，启动唤醒合并；网络与宿主失败采用指数退避，服务端 `Retry-After` 和等待状态跨重启保留。退出会取消网络工作；已进入原子切换的操作完成后再清理。实现遵循 [HTTP 条件请求和重试语义](https://www.rfc-editor.org/rfc/rfc9110.html)与[定时任务错峰实践](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)。

`src/host/codex-refresh.cjs` 通过官方 `codex plugin add` 命令刷新当前包的元数据和技能。活跃 MCP 连接通过安装目录父级的文件事件发现原子版本切换，不做每秒轮询，并通知工具与资源变化；每次请求也核对当前版本。工作台通过 MCP Apps 资源 API 加载新界面，转移内存中的导航状态，并清理旧观察器和回调。设计数据继续由 Figma 持有。

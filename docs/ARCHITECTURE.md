# 架构

一个本地伴随服务连接 Codex 与 Figma 原生 Plugin API。工具和工作台共用同一个执行环境，设计文档由 Figma 持有。

## 代码放在哪里

| 目录               | 内容                                                    |
| ------------------ | ------------------------------------------------------- |
| `src/host/`        | Node.js 本机服务：MCP、传输、调度、账号目录、安装和更新 |
| `src/figma/`       | Figma 内运行的原生执行代码、设计查询和连接界面          |
| `src/workbench/`   | Codex 工作台：文件浏览、导航和页面预览                  |
| `src/shared/`      | 跨运行环境使用的协议常量、版本比较和界面样式            |
| `scripts/`         | 构建、检查、打包发布，以及 MCP 的 shell 启动入口        |
| `skills/`          | agent 的任务导航与固定版本的公开 Plugin API 参考        |
| `test/`            | 自动测试，公共辅助代码放在 `test/helpers/`              |
| `docs/`、`assets/` | 公开文档和插件图标                                      |

根目录的 `plugin.json`、`mcp.json`、`manifest.json` 分别描述 Codex 插件、MCP 服务和 Figma 插件。生成内容位于 `build/`，发行包位于 `dist/`，两者都不提交到 Git。

## 执行与恢复

`src/host/mcp.cjs` 将工具请求交给经认证的本机回环服务 `src/host/bridge-server.cjs`，由 `src/host/execution.cjs` 调度原生客户端执行。每次操作需要确切的客户端和文件目标。云文件绑定来自已验证的文件 URL；账号目录发现不授予原生访问权限，标题不能证明文件身份。

每次编辑携带稳定的操作 ID 和请求哈希，待执行输入保存在内存中。SQLite 统一管理操作状态和回执，使用 WAL 与 FULL 同步提交；回执交付与终态一起提交。重复请求返回已有结果。连接中断或重启后，结果不确定的操作保留原始状态，由 agent 检查实际设计并确认结果，随后才能继续编辑。

读取与编辑共用调度器。Figma 原生事件和已完成写入会触发预览刷新；刷新期间保留上一张图像和视口，等待新的整页 PNG，避免与编辑争用读取。工作台的平移和缩放作用于图像视口，图层编辑与原型播放在 Figma 中完成。

## 适配边界

`src/host/catalog-sync.cjs` 与 `src/host/account-reader.js` 读取已登录的 Figma 浏览器目录，元数据和时间戳来自 Figma。这不是公开的账号全量 REST 接口，浏览器内部实现可能独立变化。扫描覆盖范围会明确记录；发现能力不可用时，已连接文件仍可读写。

界面使用宿主主题变量和共享 CSS；内联图标采用有许可证的 Lucide 路径。会话输入由 Codex 持有，插件通过 MCP Apps 提供确切的文件、客户端和页面上下文。

## 构建与检查

修改代码后运行 `npm test` 和 `npm run check`。前者构建并运行自动测试，后者检查格式、静态规则、构建一致性、插件配置与公开内容。原生执行或宿主集成变更还需要在实际编辑器和打包运行时中验收。

构建组合原生代码、打包官方 MCP Apps SDK，并收集依赖许可证。`package.json` 的 `distributionFiles` 是公开运行文件白名单的唯一来源。生成文件由源码构建，不手动维护。私有浏览器状态、宿主应用代码和开发记录不进入源码仓库或发行包。

Node.js 运行时的版本和官方归档 SHA-256 固定在 `package.json` 的 `bundledNode` 中。有效缓存通过哈希校验后直接复用，无需联网；首次下载从 Node.js 官方地址取得。打包前校验归档哈希与二进制的代码签名。更新运行时需同时更新版本和两种架构的官方哈希。

一个包版本对应不可变的发行内容。`src/host/installation.cjs` 验证安装回执，原子切换包并保留私有状态；本地只保留当前运行包和切换期间必要的恢复数据。原生构建标识来自源码内容，界面或技能变更无需重启未变化的原生内核。

## 自动更新

`src/host/update-service.cjs` 管理每用户更新服务，`src/host/updates.cjs` 接收 GitHub 发行资源。发布者使用 Ed25519 签署发布描述，客户端验证随包公钥、压缩包哈希和精确文件白名单。

接收器取得维护准入后，阻止新操作跨越切换边界。启动探测通过才提交新包，失败或中断通过恢复日志回滚；启动探测失败的压缩包会被拒绝，等待不同的发行包。排队更新在重试前重新核对发布状态，清理已撤回或被新版替代的候选包。切换或恢复完成后清理暂存目录。

私有 `updates/status.json` 统一保存调度、HTTP 缓存验证信息、签名发布描述和被拒绝的版本。接受 HTTP 304 前重新验证缓存签名。正常检查加入随机错峰，启动唤醒合并；网络与宿主失败采用指数退避，服务端 `Retry-After` 和等待状态跨重启保留。退出会取消网络工作；已进入原子切换的操作完成后再清理。实现遵循 [HTTP 条件请求和重试语义](https://www.rfc-editor.org/rfc/rfc9110.html)与[定时任务错峰实践](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)。

`src/host/codex-refresh.cjs` 通过官方 `codex plugin add` 命令刷新当前包的元数据和技能。活跃 MCP 连接通知工具与资源变化；工作台通过 MCP Apps 资源 API 加载新界面，转移内存中的导航状态，并清理旧观察器和回调。设计数据继续由 Figma 持有。
